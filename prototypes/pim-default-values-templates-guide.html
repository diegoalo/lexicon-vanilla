Templates Instead of Prepend and Append

A step-by-step guide to the prototype for someone opening it for the first time. Each step explains what you are looking at, what it means, and what you can try.

Open the prototype Labels from the prototype are quoted like this.

The idea in 1 minute

In Andrea's prototype, a folder default value applies in one of three modes: Override, Append, or Prepend. The last two add text at the start or end of the product's value when it is published.

This prototype explores another way to get the same result:

  • Simple fields (SPF, Format...): the folder gives a value and the product inherits it. This is the usual Override.
  • List fields (Tags): the folder can add its values to the product's values or replace them. This is the Append that makes sense.
  • Composed fields (channel titles and descriptions): the folder defines a template that mixes fixed text with other fields. Each product sees its final result while it is being edited.
Why a template instead of Prepend/Append

With Prepend/Append, the product's Web Title only stores a fragment ("50 ml – Travel size"), and the full title only appears on publish, joined to the folder's text. With a template, the title is built from fields that already exist (Product Line, SPF, Format, Volume...) plus a Title Note field for the part that belongs only to the product. So the field shows the final title while you edit, no data is typed twice, and the folder can place each part wherever it wants.

These are ideas to support the discussion, not a final proposal.

The example used in the prototype

It is the sunscreen case Sara shared. Folders go from general to specific, and each level adds one piece of data:

Sun Care └─ Sunscreen → Product Line = Sunscreen └─ SPF 50+ → SPF = SPF 50+ └─ Sensitive skin → Skin Type = Sensitive skin, Tags = Sun care, Sensitive skin ├─ Spray → Format = Spray ← the folder we edit │ ├─ SUN-SPF50-SENS-SPR-050 50 ml, Title Note "Travel size" │ ├─ SUN-SPF50-SENS-SPR-150 150 ml │ └─ SUN-SPF50-SENS-SPR-200 200 ml, with its own Web Title └─ Lotion → Format = Lotion ← target of case B

The three Spray products are the ones you will see in the preview tables. The 200 ml one already has a hand-written title, to show what happens when a product does not follow the template.

2

What the folder inherits and what it sets

Fields (Product Line, SPF, Format...) belong to the product type: every product has them. Folders do not add fields; they only give default values. Each level sets one, and a child folder inherits the ones above it.

In the example, each folder name matches the value it sets (the Sunscreen folder sets Product Line = Sunscreen), because that is how Sara's catalog is organized. The Set in Folder column always shows the folder name.

Changing an inherited value for Spray only: click Override on its row. The field moves to the group below, editable, with the label Overrides folder SPF 50+.

3

List fields: add or replace

  • Add to Entry Values: the folder's tags are added to the product's tags. A product with "Travel size" ends up with Sun care, Sensitive skin, and Travel size.
  • Replace: the folder's tags replace the product's tags.

This is the only place where "Append" makes sense: adding to a list is natural. In free text it is not.

4

A field with a template: Web Title (B2B)

From top to bottom:

  1. Template tells you this field uses a template.
  2. Applies as Value | Template: composed fields can give a fixed text or a template (step 7).
  3. The template box: each grey label (PRODUCT LINE, SPF...) is a field. When applied, it is replaced with that product's value. Anything between labels (the dashes) is plain text and stays as it is.
  4. Preview: what each product gets: one row per product with the title it gets. It updates live while you edit.

Look at the table:

  • The 50 ml one ends with "Travel size": that is its Title Note.
  • The 150 ml one has no Title Note, and its title ends cleanly at "150 ml" with no trailing dash. The prototype removes leftover separators when a field is empty.
  • The 200 ml one shows Own value: its title was written by hand, so the template does not affect it.
5

Editing the template

  • Type text: click anywhere in the box and type (for example, a separator or "Christmas Edition").
  • Add a field: place the cursor where you want it, click Insert Field, and pick one. The label appears at the cursor.
  • Remove a field: the × on each label removes it.
  • Check: look at the preview table; it updates right away.

Nobody has to learn a syntax like {spf}: the labels work like the Clay multiselect.

6

Help while you type

  • Repeated field: if you use the same field twice, you get Warning: SPF is used more than once. It is a warning, not an error: sometimes repeating is intended.
  • Clean separators: if a field is empty for a product, no leftovers like "– –" or trailing dashes remain.
  • One line: Enter does not add line breaks, and pasted content becomes plain text.
7

Value or Template

Only composed fields (channel titles and descriptions) have this switch. Value gives every product the same text, except the ones with their own. Template gives each product a different text, built from its own data.

8

The summary on the right

  • Inside this folder: how many products there are (3), how many follow all the folder values (2), and how many have their own Web Title (1, the 200 ml one).
  • How templates work: the three rules in short. Labels are replaced with values, typed text stays the same, and the product sees the final result while editing. Nothing is added behind the scenes on publish.

The product screen

In the Prototype panel, choose Entry inside it. The 50 ml product opens as a catalog editor would see it.

Fields fall into three kinds:

Title Note is the key to Sara's case: it is where the product writes "its" part of the title (an edition, a size, "digital"...). The folder template decides where it goes. Because it lives in its own field, it is never lost when the folder changes the template.

10

Writing your own title (and going back)

  • Write My Own: the field becomes editable and stops following the template. It starts with the current text so you do not start from scratch.
  • Use Template: drops the custom text, and the field follows the folder template again.

It is the same pattern as the CMS permissions proposal: you either follow the folder or have your own, and you can always see which state you are in.

A

Sara's case: seasonal rename

The question: for Christmas, I want every Spray title to start with "Christmas Edition". Do I have to edit product by product? Does each product lose what it had?

How to try it: in the Prototype panel, click Seasonal rename in Spray.

  • One change in the folder updates the products that follow the template (050 and 150).
  • The 50 ml product keeps its "Travel size" because it lives in its Title Note, not glued to the title.
  • The 200 ml product does not change: it has its own title, and the message says so.
  • After Christmas, you remove the text from the template and everything goes back to how it was.
B

Sara's case: moving a product to another folder

The question: if a product moves to another folder, what happens to what it inherited and to what it wrote itself?

How to try it: in the Prototype panel, click Move 50 ml to Lotion. The moved product opens.

  • What changes is what comes from the folder: Format, the folder tags (Lotion adds "Body"), and the Web Title.
  • What stays is the product's own data: Volume, Title Note, and the tags it added.

Click Start again to go back to the initial state.

Open questions

  • Live or only at creation: the prototype shows templates that keep updating products. For the PIM Beta, defaults applied at creation might be enough, with full inheritance later.
  • Languages: one template per language, or a single one with translated fields?
  • Several levels: if a parent folder and Spray both define a template for the same field, does the closest one win?

Reminder: these are ideas to help the conversation with PIM, not a decision.
